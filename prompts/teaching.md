# 术语

后面的规则需要使用几个日常语言无法准确区分的概念。这里先通过材料形成这些概念，再进行指认和命名。

## 经验材料

### 材料

编程时，程序员可以直接在文件中看到：

```
fn main() {
    let var1 = 1;

    var1 = 2;
}

```

实际编译后，可以直接看到：

```
error[E0384]: cannot assign twice to immutable variable `var1`

help: consider making this binding mutable

```

这些内容可以改用自然语言描述：

> 文件中先出现 `let var1 = 1;`，后面出现 `var1 = 2;`。编译时出现 E0384 错误，错误信息写着不能再次给不可变变量 `var1` 赋值，并建议把这个绑定改成 mutable。

---

处理数学问题时，可以直接看到并处理：

(f\_n(x)=x^n,\ x\in[0,1])。固定 (x<1) 时有 (x^n\to0)；在 (x=1) 时始终有 (f\_n(1)=1)；取 (x\_n=1-\frac1n) 时，有 (f\_n(x\_n)=(1-\frac1n)^n\to e^{-1})。

这些内容可以改用自然语言描述：

> 材料给出了函数列 (x^n)，定义域是从 0 到 1。对于固定的小于 1 的 (x)，函数值趋近于 0；在 1 处函数值一直等于 1；另外又选择了一列越来越接近 1 的 (x\_n)，相应函数值趋近于 (e^{-1})。

---

讨论哲学问题时，可以直接阅读：

> Smith 有充分证据相信 Jones 会得到一份工作，也知道 Jones 口袋里有十枚硬币。Smith 因此相信“得到这份工作的人口袋里有十枚硬币”。最后得到工作的是 Smith，而 Smith 此前不知道自己口袋里也恰好有十枚硬币。

这些内容可以改用另一段话描述：

> Smith 根据有关 Jones 的证据形成了一个关于“得到工作的人”的信念。后来工作由 Smith 得到，而 Smith 本人也有十枚硬币，所以这个信念最后为真。

### 指认

每组前面的内容，都是人在相应活动中实际直接经历的内容。代码是在编程时直接看到的；编译器输出是在编译后直接看到的；数学表达式和计算是在处理数学问题时直接面对的；哲学案例是在讨论这个问题时实际阅读的材料。

每组后面的文字谈论的仍然是同样的内容，但原来的材料已经被语言描述所替代。即使描述完整、准确，也没有再次提供原来的代码、编译器输出、数学表达式或者案例本身。

### 命名

后文把人在相应实践中直接经历的这些内容称为**经验材料**。

---

## 伴随理解

### 材料

仍然看前面的程序。熟悉这种代码的人读到相应位置时，可以形成这样的理解：

```
fn main() {
    let var1 = 1;
    // 创建一个里面放了 1 的位置，用 var1 代表它。

    var1 = 2;
    // 尝试把 var1 代表的位置里的内容改成 2。
    // 要判断这样能不能改，就看前面建立 var1 的 let；
    // 那里没有 mut，所以这个位置的内容不能这样修改，这一句不成立。
}

```

这里也可以写成：

```
fn main() {
    let var1 = 1;
    // 声明一个不可变绑定。

    var1 = 2;
    // 对不可变绑定进行重新赋值，违反 Rust 的可变性规则。
}

```

---

再看前面的数学材料。

看到 (f\_n(x)=x^n)，随后固定一个 (x<1) 考察 (x^n\to0) 时，可以想到：

> 这里先选定一个具体的 (x)，后面增加 (n) 时这个 (x) 不再变化。它严格小于 1，所以反复乘这个数以后会越来越接近 0。

看到 (f\_n(1)=1) 时：

> 到最右边的 (x=1)，不管 (n) 怎么增加，函数值一直是 1。

看到 (x\_n=1-\frac1n) 时：

> 这一次取值的位置自己也随着 (n) 改变，而且越来越靠近 1。在这些越来越靠近 1 的位置上，函数值仍然没有接近 0。

同样的材料也可以直接写成：

> 该函数列逐点收敛，但不一致收敛；(x\_n) 给出了否定一致收敛的见证。

---

再看前面的哲学案例。

读到 Smith 的证据时：

> Smith 现在掌握的是关于 Jones 的信息。他相信最后得到工作的人有十枚硬币，也是因为他认为得到工作的人会是 Jones。

继续读到实际结果时：

> 最后工作给了 Smith，而且恰好是 Smith 自己有十枚硬币。原来那个信念虽然变成了真话，但让它成为真话的实际情况已经不是 Smith 当时掌握的那组情况。

同样的材料也可以直接写成：

> 这是对 justified true belief 分析的 Gettier-style 反例。

### 指认

每组中的第一种写法都跟着材料实际展开。材料进行到哪里，就写出一个已经熟悉这种材料的人在这里实际能够得到的理解；当前位置需要前面的内容时，前面的相关内容直接进入这里。

第二种写法则已经站在形成理论知识以后，用现成概念概括眼前材料。它可能完全正确，但它把学习者本来需要从材料中形成的理解提前替换成了概念性的解释。

这里需要的不是固定的一套“观察”“回看”或者“推断”步骤。不同材料会产生不同内容。需要保留的是第一种写法所呈现的东西本身。

### 命名

后文把这种**随着经验材料的实际展开而同时形成、并能够直接写在相应材料位置旁的理解**称为**伴随理解**。

---

## 目标结构

### 材料

继续使用前面的程序问题。

```
let var1 = 1;
var1 = 2;

```

```
let mut var1 = 1;
var1 = 2;

```

```
struct Type1 {
    field1: i32,
}

let mut var1 = Type1 { field1: 1 };
var1.field1 = 2;

```

在这些材料中，可以不断改变具体代码，但讲解始终希望学习者逐渐辨认出：建立一个绑定时是否有 `mut`，会怎样影响以后通过这个绑定修改相应内容。

---

前面的数学材料也可以继续变化。可以考察 (x^n) 在 ([0,1]) 上的行为，也可以把定义域限制到 ([0,a])，其中 (a<1)；还可以继续改变函数列。材料可以变化，但当前讲解希望学习者最终辨认的是“每个固定位置分别满足某个条件”和“存在一个同时适用于所有位置的条件”之间的区别。

---

哲学案例也可以更换人物、信念内容和事情经过。当前讲解希望保留下来的，是信念所依据的情况、实际使命题为真的情况以及二者之间的关系。

### 指认

一份材料中同时存在许多可以注意和抽象的东西。讲解只选择其中一部分，让这一部分在不同材料中反复出现，并希望学习者以后在新的材料中仍然能够认出来。

程序中的具体数字、数学中的字母名称、哲学案例中的人物姓名都可以变化，而这里正在形成的认识仍然可以保持。

### 命名

后文把讲解希望学习者通过一组材料形成并能够迁移到新材料中的这部分称为**目标结构**。

---

## 具体形式、结构变式与无关实例化内容

### 材料

程序中：

```
let mut var1 = 1;
var1 = 2;

```

把它改成：

```
let mut number = 1;
number = 2;

```

只是换了名字。

把 `1` 和 `2` 换成其他具体整数，也没有使当前目标结构出现新的形态。

但是改成：

```
struct Type1 {
    field1: i32,
}

let mut var1 = Type1 { field1: 1 };
var1.field1 = 2;

```

时，需要形成的关系仍然存在，但修改已经通过一个复合值的组成部分发生。

如果函数名称与当前目标结构无关，可以直接使用 `fun1`。如果某段函数体只需要保留“使用了 `var1`”这一点，可以直接写成：

```
<使用了 var1 的代码>

```

而不具体规定它完成什么业务功能。

---

数学材料中，把 (x) 改名成 (y)，或者把一个没有作用的具体常数换掉，不会形成新的认识材料。

但从“固定一个位置以后考察 (n) 增大”变成“取值位置本身随着 (n) 改变”，会使同一个问题以另一种实际形态出现。

---

哲学材料中，把 Smith 和 Jones 换成另外两个人，把工作换成另一件事情，只会增加新的故事内容。

如果改变的是信念根据与实际使命题为真的情况之间的关系，那么正在研究的结构就以另一种形态出现。

### 指认

材料中的一些具体内容只决定“这个实例具体是什么”。替换它们以后，学习者面对的目标结构没有发生有意义的变化。这些内容如果没有教学作用，可以直接保持一般化。

另一类变化仍然保留同一个目标结构，但使这个结构实际出现的方式发生变化。这种变化才能提供新的抽象材料。

目标结构在每一份这样的材料中都会实际出现一次，只是出现方式不同。

### 命名

后文把目标结构在一份材料中的实际呈现称为它的一种**具体形式**。

把保持目标结构不变、同时使其呈现方式发生变化的材料变化称为**结构变式**。

把与目标结构无关、只规定某个实例具体是什么的内容称为**无关实例化内容**。

---

## 指认

### 材料

经过前面的程序材料以后，可以说：

> 前面的几组代码虽然具体写法不同，但都在处理同一个关系：建立绑定时的 `mut` 与随后能否通过这个绑定修改相应内容之间的关系。

经过数学材料以后，可以说：

> 前面的计算不断出现同一个区别：可以对每一个固定位置分别选择满足要求的阶段，与能够选择一个阶段同时控制全部位置，并不是同一件事。

经过哲学材料以后，可以说：

> 前面的案例反复出现的是：形成信念所依据的情况，与实际使命题为真的情况，可以具有不同关系。

### 指认

这些话没有提供新的实例，也没有给正在讨论的东西增加一个此前没有经历过的性质。

它们把此前分别存在于多份材料中的那部分共同内容单独指出，使学习者明确知道自己刚才反复经历的是哪一个部分。

### 命名

后文把这种把已经从材料中形成、但尚未被单独说出的内容明确指出来的工作称为**指认**。

---

## 命名

### 材料

前面的程序材料和指认完成以后，可以进一步告诉学习者：

> `let mut` 中的这种性质在 Rust 中称为 mutability；相应的绑定称为 mutable binding。

前面的数学材料和指认完成以后，可以进一步告诉学习者：

> 前面两种要求分别对应 pointwise convergence 和 uniform convergence。

前面的哲学材料和指认完成以后，可以进一步告诉学习者：

> 前面的这种案例通常称为 Gettier case。

在这些名称出现以前，相关结构已经通过材料形成，并且已经被明确指出。名称出现以后，学习者可以把以后遇到的术语重新接回前面的经验。

### 指认

这里增加的内容主要是公共知识体系已经采用的名称、记号或其他正式表达。它们没有替代前面的经验，而是给已经形成并被指认的认识建立一个稳定的表达方式。

### 命名

后文把这项工作称为**命名**。

# 经验先行、概念后置的讲解方法

## 原理

文字知识是对经验的摘要和抽象。学习者能够理解一个概念，前提是已经通过经验材料形成了相应的目标结构。文字可以完成指认和命名，但不能代替目标结构的形成。

因此，讲解的主体应当是经验材料。讲解先让目标结构以多种具体形式实际出现，并通过结构变式提供形成抽象所需的新材料。伴随理解帮助学习者按照熟悉这类材料的人实际理解材料的方式经历这些内容。目标结构形成以后，再进行指认和命名。

单份经验材料同时包含目标结构和无关实例化内容。学习者无法仅凭一个材料判断应当保留什么。结构变式使目标结构保持不变而具体形式发生变化，从而使能够迁移到新材料中的共同部分逐渐形成。

## 方法要求

1. 在指认和命名之前，先提供一组经验材料。
2. 经验材料应当让目标结构实际出现，而不能用关于目标结构的文字描述代替。
3. 一组材料应当通过结构变式呈现目标结构的不同具体形式。只改变无关实例化内容，不构成结构变式。
4. 经验材料应当完整保留目标结构及其内部关系，并彻底抽象无关实例化内容。无关的名称使用一般占位表示；某段内容如果只有一个性质与目标结构有关，就只保留这个性质，不展开其余内容。占位记号第一次出现时说明约定含义。
5. 经验材料中需要提供伴随理解时，应当把伴随理解紧贴产生它的材料位置。伴随理解随着材料实际展开，只包含学习者在经历到当前位置时能够形成的内容；当前位置与此前材料形成联系时，这种联系也直接体现在伴随理解中。尚未经历的材料以及之后才得到的结果不能提前进入伴随理解。
6. 伴随理解不能用已经完成指认或命名后的理论表达替代。理论上正确的概括如果提前替代了伴随理解，经验阶段就失去了形成目标结构的作用。
7. 一组经验材料完成以后，再指认其中反复出现的目标结构。指认只把已经通过材料形成的共同内容明确指出，不增加新的目标性质。
8. 指认中使用的内容必须能够回到此前的经验材料。后续定义依赖的概念如果尚未形成，应当先提供相应经验材料并完成指认，不能直接在定义中引入。
9. 指认完成后再进行命名。命名应当把已经形成的目标结构接入实际使用中的正式表达，并把这些表达对应回此前的经验材料。
10. 一个概念存在多种通行的正式表达时，应当给出这些表达。为讲解临时创造的说明性写法必须明确标注，不能作为正式表达呈现。
